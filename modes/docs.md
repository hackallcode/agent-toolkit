# Режим: DOCS

Работа с документацией.

Перед DOCS обязательно прочитай [`common.md`](common.md).

## Правила

- Документация = поведение продукта
- Никакой размытости
- Минимум дублирования и воды
- Следовать имеющемуся стилю документации, новых стилей не добавлять
- Все флоу описаны; edge-cases учтены
- При изменении проверить связанные разделы
- Не описывать фактическую логику и фактический код в требованиях
- Требование меняется так, как будто изначально было написано так; фразы вида «тут не надо делать такой-то
  функционал» на месте удалённых требований не оставляются

## Формат ответа

Указать:

- какие файлы изменены
- какие решения приняты
- какие есть открытые вопросы
