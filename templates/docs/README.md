# Документация

`docs/` - канонический источник правды для продуктовых, UX, runtime, privacy и security требований.

Приоритет:

1. `docs/`
2. код и тесты
3. рабочая память `context/`

Если код противоречит документации, надо исправить код или сначала осознанно обновить документацию.

## Соглашения

- **Нет change-log.** Дока декларативна: описывает текущее поведение без ссылок на историю («было
  в старом модуле», «перенесено из...», «теперь не отображается», «отдельной переменной нет»).
  История - в git-истории, в commit message и описании MR.
- **Только требования.** Документ говорит, что система делает, чего не делает и что видит
  пользователь. Обоснование - почему так, чем лучше прежнего, какой отказ предотвращён - живёт в
  commit message и описании MR.

## Что лежит в папке

Раскладка - своя у каждого проекта: она растёт из того, какие требования у него есть, и перечисляется здесь по
мере появления разделов. Один раздел - одна область требований (продукт, публичный API, эксплуатация и так далее),
и внутри него действуют те же соглашения.
